## 5. Defence architecture

Six layers, in evaluation order. The division matters: most failed deployments put the whole policy in layer 2, where parser differentials (SQ-INJ-03) defeat it.

**Layer 1 — Admission, before parsing.** Authenticate. Rate-limit in *work units*, not request counts (SQ-DOS-09). Cap request body size — as a coarse outer bound only, since expansion (SQ-DOS-07) makes it unsound as the real limit. Pin the method and content type; prefer POST so query text stays out of URLs and logs (SQ-CONF-07).

**Layer 2 — Parse and analyse, with the engine's own parser.** Select the grammar entry point from the protocol operation, never from the content (SQ-INJ-02). Enforce nesting-depth limits in the parser *and* in every recursive term walker (SQ-DOS-06). Apply AST and algebra size limits **after** sugar expansion (SQ-DOS-07). Feature-gate `SERVICE`, `FROM`/`FROM NAMED` dereference, `DESCRIBE`, and extension functions, on what the parse *contains* rather than on any `VERSION` declaration (SQ-INJ-05). Estimate cost and refuse above a threshold.

**Layer 3 — Authorize by constructing the dataset.** Set the dataset in the **protocol request** and refuse in-query dataset descriptions (SQ-CONF-01). The active dataset should contain exactly what the requester may see, so that protected triples never enter evaluation — this is what makes layer 4's inference channels (SQ-CONF-03) moot rather than merely narrower. Post-filtering results is a leak-rate reduction, not a confidentiality control.

**Layer 4 — Execute under enforced caps.** Wall-clock and memory limits enforced by the executor, not cooperatively. Bound *intermediate* cardinality, not just result size (SQ-DOS-01). Budget property-path expansion steps (SQ-DOS-02) and `EXISTS` inner evaluations (SQ-DOS-08). Cap string length, numeric digits and bit-length, group count, and accumulator size (SQ-DOS-03, SQ-DOS-04). Use a non-backtracking regex engine (SQ-DOS-05). Abort rather than truncate — silent truncation returns wrong answers. Enforce egress policy on the **resolved address** with redirects re-checked (SQ-NET-01, SQ-ID-02), from a distinct network identity with no ambient cloud credentials. Run least-privilege, with extension code inside the same caps (SQ-EXT-01).

**Layer 5 — Results and egress.** Opaque, per-result-set blank node labels (SQ-CONF-05). Hard result-size cap. Uniform error reporting that does not vary with hidden data or engine version (SQ-CONF-03, SQ-INJ-05). Mark non-deterministic queries uncacheable; include requester identity and effective dataset in every cache key (SQ-INT-01).

**Layer 6 — Observe.** Log the **algebra actually executed** and the **dereference targets actually resolved and contacted** — not the received text, which is the wrong artifact for exactly the reasons in SQ-INJ-03. Log `SILENT` failures server-side (SQ-NET-03). Treat query logs at the classification of the data they select over, with redaction and retention (SQ-CONF-07). Alert on query *shape* anomalies, which is the only practical detection for SQ-CONF-03 and SQ-CONF-08.

## 7. Residual risks and non-threats

### Accepted as inherent

| | Risk | Why it stays |
| --- | --- | --- |
| **RR1** | Query evaluation is computationally hard | Inherent in a pattern-matching language with `OPTIONAL` and paths. Manageable by limits (R-1), not removable. |
| **RR2** | Timing side channels | Cost-based optimization and short-circuit evaluation make execution time data-dependent by construction. Only dataset restriction (layer 3) addresses it. |
| **RR3** | Expressiveness enables inference | A sufficiently expressive query language over a dataset permits inferences the publisher did not intend. Governance, not a language fix. |
| **RR4** | Implementation divergence in error cases | Explicitly licensed by [`#extensionFunctions`](../../../spec/index.html#extensionFunctions). Interoperability cost accepted; security controls must not depend on error behaviour. |
| **RR5** | Federation moves trust outside the deployment | Inherent in federation. Endpoint allowlisting bounds it; nothing eliminates it. |

### Explicitly *not* threats

Worth stating, to keep the model honest:

- **Reading public data from a public endpoint.** P1's data is public. Enumeration and bulk download are the service working as designed; only availability (A3) and the host's position (A4, A6) need defending.
- **A query being expensive.** Expensive is not malicious. The defence is a budget, not intent detection — which is also why cost heuristics should refuse rather than attempt attribution.
- **Blank node labels differing between runs.** Required latitude, not a bug ([`#BlankNodesInResults`](../../../spec/index.html#BlankNodesInResults)). The threat is labels that are *too stable*, not unstable ones.
- **`SERVICE` and `FROM` existing.** Federation and dataset-by-reference are features. The threat is unrestricted egress, not the constructs.
- **Non-total `ORDER BY`.** A deliberate design decision ([`#modOrderBy`](../../../spec/index.html#modOrderBy)). It becomes a problem only for consumers that assume byte-stable results.

## Appendix C — Implementer checklist

Parsing

- [ ] Configurable nesting-depth limit, enforced in the parser → SQ-DOS-06
- [ ] Depth limits in every recursive term walker: comparison, ordering, hashing, serialization, `CONSTRUCT` instantiation → SQ-DOS-06
- [ ] Size limits applied to the post-expansion AST/algebra, not the request body → SQ-DOS-07
- [ ] Escape processing during parsing, single-pass, no rescan; surrogates rejected → SQ-INJ-04
- [ ] Literal length and numeric digit-count caps at parse time → SQ-DOS-04
- [ ] `LIMIT`/`OFFSET` clamped; no integer overflow at the boundary → SQ-DOS-04

Evaluation

- [ ] Enforced wall-clock and memory limits; abort, never truncate → §3.B
- [ ] Intermediate cardinality bounded, not just final result size → SQ-DOS-01
- [ ] Property-path step budget inside `ALP` → SQ-DOS-02
- [ ] `EXISTS` inner evaluations accounted against the query budget; nesting capped → SQ-DOS-08
- [ ] Group count, accumulator size, and `GROUP_CONCAT` length capped → SQ-DOS-03
- [ ] Intermediate string length capped → SQ-DOS-04
- [ ] Arbitrary-precision numeric results bounded by bit-length → SQ-DOS-04
- [ ] Non-backtracking regex engine; pattern caps; compiled-pattern cache → SQ-DOS-05

Dereference and egress

- [ ] Dereference of `FROM`/`FROM NAMED` **off** by default → SQ-NET-01
- [ ] Scheme allowlist; `file:` excluded → SQ-NET-02
- [ ] Loopback, link-local, and private ranges denied; re-checked after each redirect; no cross-scheme redirects → SQ-NET-01
- [ ] `SERVICE` off by default; endpoint allowlist enforced **on the bound value at evaluation time** → SQ-NET-03
- [ ] Variable `SERVICE` endpoints rejected in the hardened profile → SQ-NET-03, SQ-INT-02
- [ ] No credential forwarding to federated endpoints → SQ-NET-03
- [ ] Per-fetch byte and time caps; `Content-Type` enforced, not sniffed → SQ-NET-05

Results and functions

- [ ] Blank node labels opaque, per result set; never from storage ids or solution content → SQ-CONF-05
- [ ] `UUID()` from a CSPRNG (prefer v4) so the common misuse fails safe → SQ-INT-02
- [ ] `DESCRIBE` implemented as an explicit, inspectable, size-capped pattern — not an open graph walk → SQ-CONF-04
- [ ] Error messages do not vary with hidden data or engine version → SQ-CONF-03, SQ-INJ-05
- [ ] Extension functions from a static registry; function IRIs never dynamically resolved or dereferenced → SQ-EXT-01
- [ ] Non-deterministic queries flagged uncacheable → SQ-INT-01
- [ ] Documented: the chosen `DESCRIBE` algorithm, all limits and their defaults, and every registered extension's security considerations

## Appendix D — Deployer checklist

- [ ] Deployment profile identified (§2.2); threats scoped accordingly
- [ ] **Dataset set in the protocol request; in-query dataset descriptions refused** → SQ-CONF-01
- [ ] Active dataset contains exactly what the requester may see — authorization by dataset construction, not result filtering → SQ-CONF-01, SQ-CONF-03
- [ ] Read-only and read-write endpoints separated, with separate credentials; read-only enforced at the storage layer → SQ-INJ-02
- [ ] Engine runs least-privilege, with no readable secrets and no ambient cloud credentials → SQ-NET-02
- [ ] Fetcher has a distinct network identity, egress-proxied → SQ-NET-01
- [ ] Network position audited as an asset: what can the engine's host reach? → A4
- [ ] Graph IRIs carry no sensitive information; graph-name enumeration treated as privileged → SQ-CONF-02
- [ ] Rate limits denominated in work units, not request counts → SQ-DOS-09
- [ ] All engine limits reviewed and set, not left at defaults → §3.B
- [ ] Executed algebra and resolved dereference targets logged, not received text → SQ-INJ-03
- [ ] `SILENT` failures logged server-side → SQ-NET-03
- [ ] Query logs classified at the data's sensitivity; redaction and retention set → SQ-CONF-07
- [ ] Alerting on query-shape anomalies → SQ-CONF-03, SQ-CONF-08
- [ ] Policy enforced inside the engine on the algebra — not by a text-inspecting proxy → SQ-INJ-03
- [ ] Engine confirmed to process escapes during parsing (1.2 behaviour), not in a pre-pass → SQ-INJ-04

## Appendix E — Application developer checklist

- [ ] Queries built by parameterized substitution of **RDF terms**, never by string concatenation → SQ-INJ-01
- [ ] If text must be built: a library implementing [`#sec-escapes`](../../../spec/index.html#sec-escapes), and IRIs validated after resolution → SQ-INJ-01
- [ ] Input validated structurally on the parsed form, never by text patterns or denylists → SQ-INJ-01
- [ ] Nothing from the dataset used as a `SERVICE` endpoint, `GRAPH` target, regex pattern, or function name without allowlist validation → SQ-INT-02
- [ ] `RAND()`, `UUID()`, `STRUUID()` not used for tokens, secrets, or capability identifiers; generated outside the query with a CSPRNG → SQ-INT-02
- [ ] Unsalted hashes of low-entropy identifiers not treated as de-identification → SQ-CONF-06
- [ ] Mention and assertion distinguished for triple terms; a reifier's existence not treated as evidence of truth, nor its IRI as provenance → SQ-ID-03
- [ ] Results of non-deterministic queries not signed, cached, or diffed without canonicalization → SQ-INT-01
- [ ] Cache keys include requester identity and effective dataset → SQ-INT-01
- [ ] Ordering specified fully in the query where it matters; byte-equality of results not assumed → SQ-INT-01, SQ-CONF-05
- [ ] Queries carrying identifiers sent by POST; query text kept out of URLs, logs, and shared links → SQ-CONF-07
- [ ] IRIs displayed for human review normalized and bidi-isolated → SQ-ID-01
